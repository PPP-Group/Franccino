## 4. What a code reviewer would call a defect

- **Regressions of P3 final-review fixes:** the LanguageSwitcher rewrite (T4) and the forms without network-failure handling or Turnstile reset (T3).
- **Unsanitized HTML sink:** `RichText` on plain-text `area.description`/`category.description` (T6, T11).
- **Broken copy on 5 pages:** `catalog.empty` string → object (T6).
- **Verbatim duplication:**
  - `withBuildFallback` + `empty.ts` versus `apiGet` `fallback` and the existing `emptyPaginated`/`EMPTY_*` (three copies each).
  - `plan-store.ts` versus `quote/store.ts`.
  - The tab keydown handler in `FinishSelector` and `DimensionsBlock`.
  - Hand-written `alternates` versus `alternateHrefs`, plus 6 no-op `{ pt: href, en: href }`.
  - `categoryHref` defined in both `area-pages.tsx` and `products/[slug]/page.tsx`.
  - The `locale === 'pt' ? 'pt-BR' : 'en'` ternary repeated 5×; `htmlLang(locale)` already returns this.
  - `formatCentimeters` versus `formatMillimeters`.
- **i18n:** `formatDimension` default labels (letters hardcoded in TS) used by `TechTable` and `FeatureSection`.
- **a11y:** the language link has visible text "EN" but `aria-label` "English" (WCAG 2.5.3, label in name). The `.error` field message is unstyled.
- **Unsupported claims (violates Global Constraints "nunca inventar"/C4; the text comes from the prototype's `app.js`, not from PRODUCT.md or the API):**
  - `product.dimensions.madeToOrder` "Sob medida sob consulta".
  - `catalog.empty.body` "muitas peças são feitas sob medida".
  - `quote.intro` "…e a loja mais próxima".
- **Weak tests:** T7 "no fake default" (passes by tab order). T12 checks only the SSR placeholder (acknowledged). No test asserts nothing.

## 5. Proposed rulings

- **R1 (T4, LanguageSwitcher):** Keep the `7e4c9b3` mechanics: a Suspense-wrapped `LanguageLinks` with a real `href` read from the hreflang alternates, refreshed on `next/navigation` pathname/searchParams and on pointer/focus, and no `preventDefault`. T4 only restyles it: `nav.lang`, `language.short.*` visible, current locale as `<strong aria-current="true">`, `null` when there are fewer than 2 locales, and the full name in a `visually-hidden` span instead of `aria-label`. Fold in the deferred minor: initialize state with `/${locale}` and resolve in the effect. `resolveAlternateHref` stays exported from `LanguageSwitcher.tsx`; if it moves, update the test import. — Why: the P4 text reintroduces the regression the P3 re-review rejected. — Cost if wrong: modifier-click, copy-link and crawlers land on the locale home.
- **R2 (T3, forms):** The rewritten `ContactForm`/`NewsletterForm` keep P3's `try/catch/finally`: a network error becomes `failed`, and `finally` calls `turnstileRef.current?.reset()`. They also keep P3's rendering `{siteKey && <Turnstile ref={turnstileRef} siteKey={siteKey} />}` with `siteKey = getPublicEnv().NEXT_PUBLIC_TURNSTILE_SITE_KEY`, and the Turnstile API stays unchanged (tests already mock the module). The server-side `turnstile_token` error goes to the alert via `result.fieldErrors.turnstile_token ?? result.message`. `forms.css` gets a `.field .error` rule (`color: var(--alert)`). Keep `forms.turnstileLabel`. — Why: don't regress P3 final fix #5, and the P3 Turnstile needs `siteKey`. — Cost if wrong: forms hang offline, and a second submit fails on a used token.
- **R3 (T4 and consumers, build fallback):** Do not create `withBuildFallback`/`build-fallback.test.ts`. Call the fetchers directly; each one already passes `fallback` to `apiGet`, with the same semantics (network error only, `ApiError` never hidden) and existing coverage in `client.test.ts`. Create `lib/api/empty.ts` with `emptyPage` and `EMPTY_HOME`, and make `catalog.ts`/`content.ts` import from it instead of their private copies. `EMPTY_SETTINGS` lives in `lib/settings.ts` and `content.ts` imports it. — Why: one mechanism, not two, and it removes the existing triplicates. — Cost if wrong: a redundant wrapper, and an extra layer to check whenever build behavior changes.
- **R4 (T4, Settings):** Adopt the P4 `Settings` type (mirrors P2 `GeneralSettings` without `contact_recipients`; `footer_documents: { label, url }[]`). In T4, update `content.ts` and `jsonld.test.ts`. `getSettings` normalizes the response (`{ ...EMPTY_SETTINGS, ...data, footer_documents: data.footer_documents ?? [] }`), so the R6 crash-guard lives in one place. `organizationJsonLd` omits `sameAs` when there are no links, keeping the P3 test. P4 does **not** edit `docs/api.md`: add ruling R10 to the P2 ledger so the P2 T11 `SettingsController` emits and documents exactly this shape. — Why: the contract must be documented in the same PR as the API change (CLAUDE.md), and this avoids a cross-branch conflict in `docs/api.md`. — Cost if wrong: one doc paragraph to move.
- **R5 (T6, T8, T10–T12, alternates):** Detail and category metadata use `alternateHrefs(slugs, toHref)`. Static routes pass no `alternates`, because `buildMetadata` already applies `href` to every locale. — Why: keep P3 final fix #3; hardcoded `pt`/`en` ignores `NEXT_PUBLIC_SITE_LOCALES`. — Cost if wrong: duplicated loops drift.
- **R6 (T6, T11, plain text):** Render `Area.description` and `Category.description` as `<p className="lead">`, not through `RichText`. Launch/product descriptions (HTML in data-model) stay `RichText`. — Why: data-model does not mark these fields as HTML, so the API does not sanitize them (same reasoning as P3 R5). — Cost if wrong: switch to `RichText` once the API documents and sanitizes them.
- **R7 (all, messages):** Merge into the existing JSON, never replace a namespace. Specifically:
  - `catalog.empty` stays a string; P4's object becomes `catalog.emptyState` (`title`, `body`, `clear`).
  - `catalog.filters` and `catalog.pagination` merge (P4 values win on shared keys).
  - T5 adds `newTag` to the existing `catalog`.
  - `stores` keeps `allStates`/`empty`.
  - `forms` stays.
  - T12 deletes only keys with zero references (checked with grep) in both locales.
